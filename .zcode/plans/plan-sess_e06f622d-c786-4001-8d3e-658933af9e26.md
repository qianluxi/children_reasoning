### 核心设计要点

1. **统一 Question 模型**（专家 §二）：`story/entities/variables/statements(constraints)/options/answer/solution`，与专家 JSON 示例一致；**文字是表现层，logic 表达式是核心**。
2. **Logic DSL**（专家 §十一 简化）：表达式 `A_cheese && B_cheese`、`!C_cheese`、`ALL(cheese)`、`SOME_NOT(cheese)`；约束 `TRUTH_COUNT == 1`、`ORDER(A,B,C)`。
3. **Solver 是裁判**（专家 §五）：穷举所有状态（布尔 2^n；排列 n!，n≤6），过滤约束后返回全部解；**只有唯一解的题才入库**。
4. **Validator**（专家 §六）：有解、唯一解、正确选项唯一、干扰项合理性（每个错误选项都有非解状态支撑）、文字-逻辑一致性。
5. **难度引擎**（专家 §四）：score = 变量数 + 条件数 + 嵌套深度 + 推理链长 + 干扰项 + 解空间系数 → 0~2★ … 8~10★★★★★。
6. **变体生成**（专家 §十八）：同一模板换主题词（四只老鼠→四只兔子摘果子…），每次替换后重新 Solver 验证。
7. **能力模型 + 自适应**（专家 §十三）：SQLite 记录每题对错/用时/题型，按题型滑动窗口正确率画像；出题优先薄弱题型，难度按 70%目标/20%简单/10%挑战分布。
8. **儿童交互层**（专家 §十四）：界面只显示故事+emoji，不显示公式；答错给出"💡 想一想"逐步引导提示（基于 Solver 求解步骤生成提示链）；答对给星星鼓励。

### 实施步骤

1. 包骨架 + models + DSL + Solver + 对应测试
2. Validator + 难度引擎 + 测试
3. 5 个题型模板 + 主题词库 + 种子题（四只老鼠）+ 变体生成器 + 测试
4. 题库存储 + CLI（生成/验证/统计）
5. SQLite 进度存储 + 自适应出题引擎 + 测试
6. Flask Web 界面（答题、提示、解释、能力画像页）
7. README 架构文档 + 端到端验证

### 验收标准

- `pytest` 全部通过
- CLI 可批量生成 ≥100 道经 Solver 验证的唯一解题入库
- 启动 Web 后可完成：选儿童→答题→答错看逐步提示→答对得星→画像页显示各题型掌握度
